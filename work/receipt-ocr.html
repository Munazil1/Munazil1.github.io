Receipt OCR

Receipt digitization SaaS

Turns photos of receipts into clean, structured data in Google Sheets. It was deployed for a paying client and processed more than AED 20M in receipts.

AED 20M+in receipts processed

The problem

Users photograph several receipts in one shot. Extracting from the whole image merged receipts together or skipped some, so a result could look clean and still be wrong.

How it works

  1. Capture

    The user uploads one photo containing several receipts.

  2. Locate each receipt

    Azure's layout model returns the boundaries of every receipt in the image.

  3. Crop

    Each receipt is cut out and handled on its own.

  4. Extract and normalize

    Fields are extracted, then GPT-4.1 maps them into one consistent schema.

  5. Export

    Confirmed receipts export to Google Sheets in one click.

What I built

The hard part was detection. I worked through four approaches, from OpenCV contour detection and projection analysis to Azure Document Intelligence's layout model, which returns receipt boundaries directly and proved far more accurate on real customer photos.

Around that sits a FastAPI and React application with PostgreSQL, JWT authentication with OTP and background token refresh, real-time processing status, and multiple Celery workers that process uploads in parallel.

Key decisions

  • Document structure over pixel tricks

    Contour and projection heuristics were brittle on real photos. A layout model that understands document structure held up.

  • Detect first, extract second

    Splitting the problem means each receipt is extracted on its own, so one difficult receipt can't corrupt the others.

  • Parallel by default

    Multiple Celery workers keep large uploads moving instead of queueing behind each other.

The code belongs to Pure Magic IT and its client, so it isn't public. I'm happy to walk through it in an interview.
