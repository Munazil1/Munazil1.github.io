DocFoundry

KYC and document verification SaaS

A multi-tenant platform that verifies customer identity documents automatically. It runs in production for two client organizations.

The problem

Client teams checked customer identity documents by hand: reading fields off scans, comparing selfies to ID photos, and preparing exports that met Dubai's DTCM/DET requirements. It was slow, inconsistent, and hard to audit.

How it works

  1. Upload

    Customers or staff upload ID documents, one at a time or in bulk.

  2. Extract fields

    Azure Document Intelligence reads the document and returns structured fields.

  3. Match the face

    InsightFace compares the selfie with the photo on the ID.

  4. Store securely

    Records are kept per client organization, with access controlled by role.

  5. Export

    Verified records export in a DTCM/DET-compliant format.

What I built

I built the FastAPI backend end to end: JWT authentication with refresh tokens, role-based access middleware with four roles, document storage, purchase-order and reporting modules, and more than eleven REST endpoints. Celery and Redis handle background work, and the React frontend sits on top.

The full stack runs in Docker behind Nginx on an Azure VM, and GitHub Actions deploys every change automatically.

Key decisions

  • Multi-tenant from the start

    Each client's data is isolated by design, so a second organization could be onboarded without rebuilding anything.

  • Tests before scale

    Reaching 85% backend test coverage with pytest meant a change for one client couldn't quietly break another.

  • A separate path for volume

    A dedicated bulk-upload pipeline processes large batches of documents in the background.

The code belongs to Pure Magic IT and its client, so it isn't public. I'm happy to walk through it in an interview.
