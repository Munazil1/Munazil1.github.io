DocFoundry

KYC and document verification

In production for 2 client organizations, with 85% test coverage.

  1. ID document uploaded
  2. Fields extracted with OCR
  3. Face matched to ID photo
  4. Stored with role-based access
  5. Compliant export
Problem
Clients verified customer identity documents by hand and needed exports that meet Dubai's DTCM/DET requirements.
What I built
A multi-tenant verification platform: Azure Document Intelligence extracts ID fields, InsightFace matches the selfie to the document photo, and a FastAPI backend handles JWT auth, four-role access control, and bulk uploads.
Stack
Python, FastAPI, React, PostgreSQL, Celery, Redis, Azure Document Intelligence, InsightFace, Docker, GitHub Actions

Receipt OCR

Receipt digitization

Processed AED 20M+ in receipts for a paying client.

  1. One photo, several receipts
  2. Each receipt located
  3. Cropped one by one
  4. Fields extracted and normalized
  5. Exported to Google Sheets
Problem
Users photograph several receipts at once. Extracting from the whole image merged or skipped receipts, so a clean-looking result could still be wrong.
What I built
I moved detection from OpenCV contour and projection heuristics to Azure's layout model, which returns each receipt's boundaries for accurate cropping. GPT-4.1 then normalizes the extracted fields, with Celery workers processing uploads in parallel.
Stack
Python, FastAPI, React, PostgreSQL, Celery, Redis, Azure Document Intelligence, GPT-4.1, Google Sheets API

WorkTrack

AI event staffing

A 3-hour staffing task now takes under 10 seconds.

  1. Full staff pool
  2. Rules filter: availability, conflicts, leave
  3. LLM ranks the shortlist
  4. Decision snapshot saved
  5. Admin approves
Problem
Staff were assigned to events by hand from spreadsheets, taking about 3 hours per event and causing double-bookings.
What I built
A two-phase pipeline: plain code removes anyone unavailable or conflicted, and only the shortlist goes to an OpenAI model for ranking. That keeps cost and latency low, and every recommendation is saved as an immutable snapshot for audit. The platform has 60+ REST endpoints and multi-tenant admin.
Stack
Python, FastAPI, React, PostgreSQL, Alembic, OpenAI, Docker, Azure, GitHub Actions

ClaimAssist

Insurance claims assessment

Reviewers only see the claims that need their judgment.

  1. Claim via email, WhatsApp, or camera
  2. Plate and VIN checked
  3. Photos and 360° video assessed
  4. Uncertain or severe claims reviewed
  5. Audit log written
Problem
Claims arrived through scattered channels and were assessed manually, with no reliable record when an assessment was disputed.
What I built
A multi-model pipeline: GPT assesses photos and Gemini 2.5 Pro assesses 360° walkaround video for damage severity, repair cost, and fraud signals. OCR checks the plate and VIN against policy records, low-confidence claims go to a human queue, and every decision lands in a tamper-resistant audit log.
Stack
n8n, OpenAI, Google Gemini 2.5 Pro, Azure Blob Storage, PostgreSQL, OCR

How I work

  • Start from the decision. Before building, I ask what the client needs to decide, then show a working version early and adjust to their feedback.
  • Code for rules, models for judgment. Anything a plain rule can decide never reaches the model. It's cheaper, faster, and easier to debug.
  • Plan for the model being wrong. Confidence scores, human review, and audit trails are part of the first version, not added later.
  • Deployment is part of the product. I've shipped into client infrastructure with restricted networks and replicated databases, and I treat that work as seriously as the model.
